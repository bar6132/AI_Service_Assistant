# עוזר AI לשירות לקוחות באתר מסחר

אבטיפוס שמקבל פנייה חופשית של לקוח מחובר, מבין אותה באמצעות מודל שפה, ומקבל **החלטה דטרמיניסטית בקוד** על סמך מדיניות השירות ונתוני ההזמנה. העיקרון המרכזי: **המודל מבין ומנסח; הקוד מחליט ומבצע**.

מסמך התכנון המלא: [`Docs/AI_Service_Assistant_Design.md`](../Docs/AI_Service_Assistant_Design.md) — ארכיטקטורה, טבלת החלטות, פרומפטים, תוכנית בדיקות. מסמך המטלה המקורית (`Docs/AIEngineerTest.md`) אינו כלול במאגר הציבורי (ראו `.gitignore` בשורש) — זהו תוכן המטלה עצמו, לא תוצר של הפתרון.

## הדגמה ויזואלית (Demo)

[`progress/Demo/request-pipeline.html`](progress/Demo/request-pipeline.html) — עמוד HTML עצמאי (בלי שרת, מפתח API או התקנה; כשיש רשת נטענים גופנים מ-Google Fonts, ובלי רשת — גופני מערכת) שמראה ויזואלית איך פנייה עוברת דרך כל קובץ במערכת: LLM #1 (חילוץ) → שליפת הזמנה → מנוע המדיניות → פתיחת בקשת שירות → LLM #2 (ניסוח) → Reply Guard → תשובה. כולל 4 תרחישים אמיתיים (מתוך `progress/10`) שאפשר לעבור ביניהם צעד-צעד, עם קוד ה-JSON האמיתי בכל שלב. פותחים ישירות בדפדפן (double-click על הקובץ, או `start progress/Demo/request-pipeline.html` ב-Windows).

## דרישות סביבה

- Python 3.11+ (פותח ונבדק על 3.14)
- מפתח Gemini (`GEMINI_API_KEY`) — הספק שכל מקרי הבדיקה הורצו מולו, וברירת המחדל (`PROVIDERS=gemini`). הקוד תומך גם ב-xAI Grok (`XAI_API_KEY`) ובשרת מקומי, אבל אלה לא נבדקו. ספק בלי מפתח מדולג, ושם ספק לא מוכר (למשל `groq`) נעצר בהפעלה עם הודעת שגיאה ברורה.

## התקנה

```bash
cd matrix-ai-service
python -m venv .venv        # יוצר סביבה וירטואלית מבודדת בתיקיית .venv/
```

הפעלת הסביבה הווירטואלית (תלוי בשל שבו מריצים):
```bash
# Windows – PowerShell
.venv\Scripts\Activate.ps1

# Windows – Git Bash
source .venv/Scripts/activate

# macOS / Linux
source .venv/bin/activate
```
לאחר ההפעלה שורת הפרומפט תתחיל ב-`(.venv)`. `.venv/` לא נכלל בבקרת גרסאות (`.gitignore`).

```bash
pip install -r requirements.txt
cp .env.example .env
# ערכו את .env והכניסו GEMINI_API_KEY=...
```

`.env` **לא** נכלל בבקרת גרסאות (`.gitignore`) — אין בו סיסמאות/מפתחות בהגשה. `TODAY=2026-09-22` ב-`.env.example` מקבע את תאריך הבדיקה של המטלה; בלעדיו, החישובים (איחור, חלון החזרה) נעשים לפי התאריך הנוכחי ב-Asia/Jerusalem.

## הפעלה

לדוגמאות מלאות עם פלט אמיתי מכל 10 מקרי הבדיקה (כולל שאלת הבהרה + הרצה חוזרת עם `--context`, תקלה מדומה, ובדיקת מסד הנתונים) — ראו [`progress/10-בדיקות-ותוצאות.md`](progress/10-בדיקות-ותוצאות.md) (עברית) / [`progress/en/10-tests-and-results.md`](progress/en/10-tests-and-results.md) (אנגלית). לתצוגה ויזואלית של אותה זרימה בלי להריץ כלום — [`progress/Demo/request-pipeline.html`](progress/Demo/request-pipeline.html). למטה רק תמצית פקודות:

```bash
# בקשה בסיסית
python run.py C-101 "אני רוצה לבטל את הזמנה ORD-1001."

# תשובת המשך להבהרה, עם הקשר מהשיחה הקודמת (פורמט מובנה: intent:ORD-XXXX)
python run.py C-101 "לא נפתח" --context "return:ORD-1003"

# דימוי כשל שירות הזמנות
python run.py C-101 "..." --simulate-outage

# עם לוגים (ספק, latency, guard) ל-stderr
python run.py C-101 "..." -v

# תאריך קובע אחר (ברירת מחדל: TODAY מ-.env, אחרת התאריך הנוכחי)
python run.py C-101 "..." --today 2026-09-22
```

הפלט הוא JSON יחיד ל-stdout: `intent`, `action`, `reply`, `order_id`, `source_ids`, `service_request`, `reason`. גם שגיאות (קלט לא תקין, הגדרת ספקים שגויה) מוחזרות כ-JSON עם `error`, בקוד יציאה 2.

בדיקות אוטומטיות (בלי מודל אמיתי ובלי מפתח API — 129 בדיקות: טבלת ההחלטות, Reply Guard, התזמור, בסיס הנתונים ושכבת המודל מול שרת מזויף; כיסוי 93%. פירוט ב-[`progress/12-בדיקות-יחידה.md`](progress/12-בדיקות-יחידה.md) וב-[`progress/13-סגירת-פערים.md`](progress/13-סגירת-פערים.md)) — מריצים מתיקיית `matrix-ai-service/` (לא מתוך `tests/`), ודרך `python -m` כדי להימנע מבעיות launcher כשיש כמה התקנות Python במחשב:
```bash
python -m pytest
```

## מבנה הפרויקט

```
data/orders.json, policies.json     נתוני הבדיקה — מהמטלה, ללא שינוי מלבד פורמט תאריך
data/service_requests.db            נוצר אוטומטית בהרצה ראשונה (SQLite)
src/models.py                       חוזי נתונים (Pydantic)
src/policy_engine.py                טבלת ההחלטות (קוד דטרמיניסטי)
src/order_service.py                שליפת הזמנה מדומה + בדיקת בעלות
src/service_requests.py             פתיחת בקשת שירות מדומה → SQLite; מזהה מה-DB, בקשה פתוחה אחת לכל (הזמנה, סוג)
src/llm.py                          לקוח OpenAI-compatible + שרשרת ספקים
src/prompts.py                      פרומפט חילוץ (עם few-shot) + פרומפט ניסוח
src/order_ids.py                    אימות מספרי הזמנה מול הטקסט (הקוד מאמת את מה שהמודל הציע)
src/reply_guard.py                  בדיקה דטרמיניסטית של התשובה (עברית ואנגלית) + תבניות fallback
src/agent.py                        התזמור — מחבר הכול לזרימה אחת
run.py                              CLI
tests/                              129 בדיקות אוטומטיות, בלי מודל אמיתי
progress/                           תיעוד שלב-אחר-שלב בעברית, כל החלטה מצוטטת מהמקור
progress/en/                        אותו תיעוד באנגלית
progress/Demo/request-pipeline.html דף HTML עצמאי — תצוגה ויזואלית של הזרימה, בלי הרצה
```

## תוצאות בדיקות

כל 8 מקרי המטלה + 2 מקרים נוספים הורצו בפועל מול **Gemini 3.1 Flash-Lite** (לא סימולציה) — כולם עברו, גם בהרצה החוזרת אחרי סבב סגירת הפערים (30.09.2026). טבלה מלאה, כולל דוגמת הרצה עם רשומת בקשת שירות שנוצרה, ב-[`progress/10-בדיקות-ותוצאות.md`](progress/10-בדיקות-ותוצאות.md) (עברית) / [`progress/en/10-tests-and-results.md`](progress/en/10-tests-and-results.md) (אנגלית).

**שיפור אחד בעקבות בדיקה (נדרש במטלה):** מקרה 5 (החזרה, מצב מוצר לא ידוע) נפל בהתחלה ל-fallback גנרי במקום לשאול שאלה ממוקדת, כי ה-Guard פסל תאריך תקין שנכתב בפורמט שונה מ"חבילת העובדות" (`12.09.2026` מול `2026-09-12`) — false positive. אובחן, תוקן (נרמול תאריכים ב-`reply_guard.py`), ואומת מחדש. פירוט מלא, כולל שיפור שני שנמצא באותה סבב, באותו קובץ תוצאות.

## מגבלות ידועות

- מדיניות "לא נפתח" מבוססת הצהרת לקוח, לא מאומתת (בייצור: אימות בקליטת ההחזרה).
- **אין הערכה סטטיסטית:** 10 מקרים, ספק אחד, הרצה אחת לכל מקרה (ועוד הרצה חוזרת). זה מוכיח את החיווט, לא את האמינות. סוללת ניסוחים חלופיים והשוואת ספקים (תכנון, סעיף 18) לא מומשה.
- **ה-Reply Guard הוא רשימת חסימה**, ולכן לא שלם; ההגנה העיקרית היא שהמודל השני מקבל רק חבילת עובדות סגורה. ניסוח לגיטימי שנחסם עובר לתבנית קבועה.
- **Grok והשרת המקומי** נתמכים בקוד אבל לא נבדקו.
- **טיפול בנתונים:** טקסט הפנייה נשלח לספק המודל (Google, דרך ה-API). אין סינון מידע אישי לפני הקריאה, ותנאי השימוש בנתונים ב-free tier לא נבדקו.
- **מקביליות:** ייצור מזהה הבקשה בטוח לכתיבות מקבילות; שירות בו-זמני (HTTP, async) לא נבנה — ראו [`progress/11-שדרוג-לרב-משתמשים.md`](progress/11-שדרוג-לרב-משתמשים.md).
- רשימה מלאה: `Docs/AI_Service_Assistant_Design.md`, סעיף 24.
